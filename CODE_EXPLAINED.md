# C Banking System — Beginner Code Guide\n\nThis document explains the current banking_system.c code in simple language.\n\n## 1. Overall program flow\n\nmain() -> mainMenu() -> Create Account / Login / List Accounts / Exit\nLogin -> authenticate() -> accountMenu() -> Balance / Deposit / Withdraw / Transfer / History / Delete / Logout\n\nData is stored in two binary files:\n- accounts.dat: account records\n- transactions.dat: transaction records\n\n## 2. Header files\n\n- ctype.h: character checks such as isdigit(), isspace(), iscntrl().\n- errno.h: detects conversion errors from strtol() and strtod().\n- float.h: floating-point limits such as DBL_MAX.\n- limits.h: integer limits such as INT_MAX and INT_MIN.\n- math.h: isfinite(), used to reject invalid money values.\n- stdio.h: printf(), fgets(), fopen(), fread(), fwrite(), fclose() and file/input/output work.\n- stdlib.h: number conversion and general utilities.\n- string.h: strlen(), strcmp(), strncpy(), memset() and string/memory work.\n- time.h: creates transaction timestamps.\n\n## 3. Constants\n\nConstants define values used repeatedly, such as filenames, maximum name length, PIN length, account ID length, 2026 account year, and allowed transaction limits.\n\nUsing constants is better than scattering magic numbers throughout the program.\n\n## 4. Account structure\n\nAccount stores one customer's data:\n- accountNumber: ID such as 2026/1\n- name: customer's name\n- pin: four-digit PIN\n- balance: current balance\n- active: 1 means active, 0 means deleted\n\n## 5. Transaction structure\n\nTransaction stores one banking event:\n- accountNumber: account involved\n- type: DEPOSIT, WITHDRAW, TRANSFER_OUT, TRANSFER_IN, etc.\n- amount: money involved\n- balanceAfter: balance after the event\n- timestamp: date and time\n- description: readable explanation\n\n## 6. Input functions\n\nclearInputBuffer(): removes leftover keyboard characters.\nreadLine(): safely reads a line and removes the newline.\nisBlank(): checks whether text contains only whitespace.\nisValidName(): rejects empty names and control characters.\nreadInt(): safely converts user input into an integer and checks for errors.\nreadAmount(): converts money input and checks limits, invalid values, infinity and NaN.\nisValidPin(): requires exactly four numeric digits.\npauseScreen(): waits for Enter.\n\n## 7. Account-number functions\n\nisValidAccountNumber(): checks the YYYY/N format and requires the year 2026 and a positive sequence.\n\ngetNextAccountNumber(): scans accounts.dat, finds the largest existing 2026 sequence and creates the next one.\n\nExample:\n2026/1, 2026/2, 2026/7 -> next account is 2026/8.\n\n## 8. Account file functions\n\nfindAccount(): searches accounts.dat for a matching active account.\n\nsaveNewAccount(): appends a new Account record to accounts.dat.\n\nupdateAccount(): finds an existing account and overwrites that record with new data.\n\nImportant C idea: fopen modes:\n- rb = read binary\n- ab = append binary\n- rb+ = read and write binary\n\n## 9. Transaction logging\n\nlogTransaction(): creates a Transaction and appends it to transactions.dat.\n\nIt records account number, transaction type, amount, new balance, timestamp and description.\n\ntime(), localtime() and strftime() are used to create the timestamp.\n\n## 10. Account creation\n\ncreateAccount() combines several smaller functions.\n\nFlow:\n1. Generate account number.\n2. Read and validate name.\n3. Read and validate PIN.\n4. Read and validate initial deposit.\n5. Save account.\n6. Log the initial deposit.\n7. Show the new account number.\n\n## 11. Authentication\n\nauthenticate() performs login.\n\nFlow:\n1. Read account number.\n2. Validate its format.\n3. Find the active account.\n4. Read PIN.\n5. Compare PIN with stored PIN.\n6. Return 1 for success or 0 for failure.\n\n## 12. Deposit\n\ndepositMoney() reads an amount, validates it, checks for balance overflow, increases the balance, saves the account and logs the deposit.\n\nIf saving fails, the in-memory balance is restored.\n\n## 13. Withdrawal\n\nwithdrawMoney() reads and validates an amount, checks that the account has enough money, subtracts the amount, saves the account and logs the withdrawal.\n\nMain rule:\nwithdrawal amount must be less than or equal to the current balance.\n\n## 14. Balance\n\ncheckBalance() only displays account number, name and balance.\n\nThe parameter is const because this function should not modify the account.\n\n## 15. Transfer\n\ntransferMoney() moves money between two active accounts.\n\nFlow:\n1. Read recipient ID.\n2. Validate recipient ID.\n3. Reject transferring to the same account.\n4. Find recipient.\n5. Read transfer amount.\n6. Check sender balance.\n7. Check recipient balance will not overflow.\n8. Subtract from sender.\n9. Add to receiver.\n10. Save both accounts.\n11. Log TRANSFER_OUT and TRANSFER_IN.\n\nRollback is used when updating the receiver fails: the sender is restored to its previous balance.\n\n## 16. Transaction history\n\nviewTransactionHistory() reads transactions.dat one record at a time.\n\nIt prints only transactions whose accountNumber matches the logged-in account.\n\nIt also checks for file errors and incomplete records.\n\n## 17. Account directory\n\nlistAllAccounts() reads accounts.dat and displays only records with active == 1.\n\nThis is marked as a demo directory because exposing customer account information publicly would not be appropriate for real banking software.\n\n## 18. Delete account\n\ndeleteAccount() requires the balance to be zero and asks the user to type yes.\n\nThe record is not physically removed. Instead active is changed from 1 to 0.\n\nThis is called a soft delete.\n\nThe current code also writes ACCOUNT_DELETED to transaction history, so the deletion is recorded.\n\n## 19. Account menu\n\naccountMenu() is the menu shown after login.\n\nThe switch statement connects menu numbers to functions:\n- 1 -> checkBalance()\n- 2 -> depositMoney()\n- 3 -> withdrawMoney()\n- 4 -> transferMoney()\n- 5 -> viewTransactionHistory()\n- 6 -> deleteAccount()\n- 7 -> logout\n\n## 20. Main menu\n\nmainMenu() is the top-level controller.\n\nIt connects:\n- 1 -> createAccount()\n- 2 -> authenticate() and accountMenu()\n- 3 -> listAllAccounts()\n- 4 -> exit\n\n## 21. main()\n\nmain() is where execution starts.\n\nIt prints the welcome message, calls mainMenu(), and returns 0 when the program ends successfully.\n\n## 22. C concepts this project teaches\n\n- Variables: store values such as balance and menu choices.\n- Arrays: store names, PINs, IDs and descriptions.\n- Strings: handled with strlen(), strcmp(), strncpy() and related functions.\n- Structs: Account and Transaction group related data.\n- Pointers: allow functions to work with existing data, for example &acc.\n- Functions: split a large program into smaller jobs.\n- if/else: validation and business rules.\n- while loops: menus and file reading.\n- switch: menu selection.\n- File I/O: persistent storage using fopen(), fread(), fwrite(), fseek(), fclose().\n- Error handling: checks failed input, file operations and updates.\n- Binary files: complete C structures are stored directly in .dat files.\n- Rollback: restores state after a failed update.\n\n## 23. Best learning order\n\nDo not try to memorize the whole project at once.\n\nLearn in this order:\n1. main()\n2. mainMenu()\n3. Account struct\n4. createAccount()\n5. saveNewAccount()\n6. findAccount()\n7. authenticate()\n8. depositMoney()\n9. withdrawMoney()\n10. transferMoney()\n11. logTransaction()\n12. accountMenu()\n\n## 24. One mental model\n\nInput -> Validate -> Change data -> Save to file -> Log transaction -> Show result\n\nThis pattern appears throughout the project.\n\n## 25. Important project limitation\n\nThis is an educational C project, not production banking software.\nThe current project stores PIN data locally and uses double for money. Real financial software would need stronger security, authentication, database transactions, auditing and appropriate monetary representations.
